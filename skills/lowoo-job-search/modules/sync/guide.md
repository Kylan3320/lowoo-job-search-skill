# 招聘平台资料同步

## 确定本轮范围

- 先确定各平台要改的栏目、附件及语言。涉及附件且用户未指定语言时，沿用个人画像中的平台语言偏好；没有既有偏好时按本次材料确定，确有歧义才询问。指定单站、单项或单一语言时，按指定范围执行。
- 按用户指定的正式资料更新。未指定时从本次材料或 `profile/求职画像.md` 登记的简历索引定位当前正式 PDF 和对应语言的完整在线文案。本轮指令优先，正式资料提供要同步的内容，个人档案补足已确认的偏好与字段。资料冲突且无法判断时先完成其他项。
- 用平台现有记录匹配对象。实习按公司和月份，项目按别名、用途和时间。唯一匹配时原位更新，内容一致时跳过，匹配含糊时先处理其他项。附件按版本核对，同名如仍有疑问，用预览、详情或上传时间核实。附件满时先找平台的替换入口，删除按工具规则处理。职位分类只能近似匹配时，在可用字段保留准确岗位。职责和业绩按平台字段填写，业绩数据保留适用条件。

## 核对改动，再操作页面

“同步对应更新”时，有可确认的上一版正式稿就先对比新旧两版，再核对平台的相关字段。没有可用旧版时按指定项目与平台现值比较。保留职责、日期、项目技能关联等无关的现有信息。用户明确要求全面校准时才扩到整个目标栏目。

同一事实以本次指定版本为准，画像中更新的动态数字单独说明。优先用对应语言完整稿的原句，只按平台字段或长度做必要拆分。概述说项目用途，职责说候选人实际承担的工作，业绩说结果和适用条件，同一卖点只写一次。提交前将目标值与正式稿核对，再把结果与平台现值比较。一项内容相同就跳过，只有附件请求就不改在线正文。

## 执行本轮变更

按[主入口](../../SKILL.md)选择工具和接管页面。同一表单一次填完本次有变化的字段。附件满位先找原位替换入口。中断时在当前对话保留平台、记录、待填值和最后一次提交结果，恢复时可直接对照。

按平台读取相应手册：[BOSS 直聘](references/boss.md)、[猎聘](references/liepin.md)、[前程无忧](references/51job.md)、[牛客](references/nowcoder.md)、[领英](references/linkedin.md)。

## 保存与验收

从正式页面读回实际改动的字段，逐项与本轮目标值比对；列表只显示项目名、日期或截断正文时，打开原记录详情核对目标字段。只补查本轮操作可能连带改变的字段。

| 请求项 | 通过条件 |
| --- | --- |
| 附件 | 正式列表显示本轮目标文件和版本。有审核状态时如实记录。 |
| 实习与项目 | 核对匹配到的原记录及修改后的具体字段。业绩正文核对数值、单位、测试环境与计时范围，职责正文核对个人贡献。角色、月份和实习标记只在本轮变更或解析可能影响时检查。 |
| 其他在线字段 | 在正式页面核对目标值。解析造成且有原值可证实的变动按工具规则恢复后读回。 |
| 作品 | 正式作品区显示目标媒体或链接，平台提供审核状态时记录。有替换或删除时按平台手册核对。 |
| 公司屏蔽 | 在保存后的屏蔽列表核对公司全称。界面只提供复选框或计数时，说明实际证据。 |

每项用一条可见证据或具体原因交代结果。区分已一致、已保存、待审核和阻塞。待审核仅在用户要求等到通过时继续监看。
