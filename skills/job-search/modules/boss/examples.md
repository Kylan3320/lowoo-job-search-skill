# BOSS 招呼语正反例

## 正例｜ToC AI 产品岗位

JD 看重独立做产品、AI Coding、理解用户需求和持续迭代。先交代做过什么，再用两个产品的实际用法讲清楚个人贡献。

> 我独立从 0 到 1 做过两个面向消费者的 AI 工具。做周末行程工具时，试用的人告诉我，取消一个景点就得重排一整天。我把修改放到了每一站，用户可以保留已经订好的其他行程。下个月可以到岗，每周 4 天。
>
> 另一个是桌游规则助手。为了让玩家能核对裁定，我给回答加了规则书页码，还把试玩中容易答错版本的问题留作回归用例。
>
> 希望和您进一步沟通，期待您的回复。

## 正例｜按三个 JD 要求展开的 B 端 AI 产品实习

岗位同时提到 PRD、Vibe Coding 和 AI Native。开头先说与业务人员、研发怎样配合，中间每个关键词都接一件具体做过的事，岗位明确要看交互演示，可以在结尾给对应作品。

> 做过仓配运营工作台，交付过 Web 版 PRD 和高保真原型。跟调度员交班时，我发现他们得翻两张表才能知道异常件由谁接手，就把责任人和处理记录放回同一张工单。暑期可以连续实习，每周到岗 4 天。
>
> 1. **Vibe Coding**  
>    我用 Vibe Coding 写过一版可以操作的工单列表。评审时，调度员直接拿昨天的异常件试走了一遍，我们才发现跨班次转交还缺一个接收人。
> 2. **AI Native**  
>    我平时用 Codex 做原型，也会拿模型厂商发布的示例试自己的问题。做工单摘要时，我专门留了一组多次转交的记录，检查摘要有没有漏掉最后一次承诺。
>
> 方便的话，我可以发您工作台的交互演示。
>
> 希望和您进一步沟通，期待您的回复。

## 换岗位时怎么选经历

- **JD 偏 B 端用研、PRD 和原型**  
  「我跟调度员一起看过早晚班的交接记录，发现最费时间的是找上一班最后联系了谁。后来把责任人和处理记录放在同一张工单，交付了 PRD 和原型。」岗位更看重协作时，接着讲研发评审时怎样确定跨班次的接收人。
- **JD 偏 Agent 任务拆解、工具调用和评测**  
  「我做过一个桌游规则助手，玩家可以直接查询不同版本的规则。我整理了试玩中答错的问题，用来评测规则检索的效果。」招聘方关注评测方法时，可以再举一类有代表性的错题。
- **JD 偏工作流和业务验收**  
  「我把异常工单的交班汇总改成了自动流程。同一批 40 张工单里，漏记最新进度的从 7 张降到了 1 张。」这里的样本数给改善幅度提供了分母。其他业务量和故障类别没有出现在正文里。

## 反例｜把笼统的自述改成聊天里会说的话

| 反例 | 改法 |
| --- | --- |
| 「您好，我看到贵司正在招聘……」 | 用最贴岗位的一段经历开头，比如「在仓配团队做过运营工作台」。 |
| 两个项目连续用「我做了个……」开场，再逐个列能力 | 先交代「我独立从 0 到 1 做过两个自己也在用的 AI 工具」，再分别写使用场景和自己的分工。 |
| 「Codex 也用得比较多。有了想法，我会先用它做个能上手试的版本，边用边改。」 | 用户确实长期深度使用时，直接写「我是 Codex 深度用户」。需要证明动手能力时，接一个能看的交付，比如「工单列表那版可以直接试跨班次转交」。 |
| 「平时在 X 和 Reddit 上看 AI 新产品和新玩法。」 | 写清关注什么，例如「在 X 和 Reddit 上跟进 AI 前沿进展，也会看头部 AI 厂商发布的技术文章」。岗位重视落地时，接一句文章中的方法用在哪个项目。 |
| 「具备从需求洞察到产品落地的全链路能力，擅长用 AI 赋能业务。」 | 点名实际动作，比如「跟调度员看交班记录，梳理异常件的转交条件，再把流程做成可以操作的原型」。 |
| 「支持问答。支持引用。持续迭代。」 | 放回使用场景，比如「大家对一条规则有分歧时，可以直接问助手，点回答里的页码就能翻到原文」。 |
| 「我把日志、工单、回访表逐份过了一遍，看有没有漏报、有没有错报，再一条条补……」 | 把个人交付或已经核实的改善放在前面。招聘方问及验收方法时，再展开最能说明判断的一项。 |
